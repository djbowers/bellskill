## Vision

### 10x Check
The pattern-debt engine stops being a chart on the History page and becomes the training brain of Bellskill. Every movement carries a pattern-credit vector; debt is a ledger the whole app reads. The recommender names the one 20-minute session that pays down the most debt. Every surface that shows a movement (picker, swap dialog, session card) shows what it pays for.

### Platonic Ideal
Open the app and know in one glance whether you're whole. If not, the app hands you the exact session that makes you whole, and after logging it you watch the debt drain. Balance becomes a feedback loop you feel inside a single workout, not a report you check.

## Findings that motivated the scope
- Attribution is single-bucket and get-up name-detection wins first: a Turkish get-up credits ZERO rotation/push/carry — TGU-heavy users show phantom red rotation debt (SQL `pattern_debt_window`, migration 20260729000003).
- Catalog has no anti-rotation/anti-extension values; the CHECK constraint (20260709000000_slim_movements_catalog.sql:73) forbids them. Planks etc. are shoehorned into "Rotational" (49 rows).
- Thin buckets: carry has 9 catalog movements, get_up 4 (name-regex only) vs squat 51 / push 66 — structurally prone to permanent red.
- `TARGET_CADENCE_DAYS = 7` is documented and exported but never used in the scoring math.
- UI mixes three vocabularies for one number: debt (model), readiness = 100−debt (bars), Due/Overdue (band labels).
- No user-preferences infrastructure exists; `profiles` is the natural host for pattern preferences.

## Outside-Voice Revisions (2026-08-03, all user-approved X1–X5)

Cross-model review (Claude subagent outside voice) overturned five earlier calls:
- **X1** Boolean multi-pattern tags with equal credit, applied in the shared TS scorer; SQL returns raw per-movement aggregates. No fractional weights, no normalization, no SQL/TS parity test.
- **X2** 8 scored patterns, not 9: anti-rotation/anti-extension become catalog sub-labels rolling up into one scored `core` pattern. `BALANCE_SPREAD`/bands recalibrated for 8.
- **X3** Sequencing: Phase 1 correctness → debt-optimal premium session (PROD-142 path) → engagement surfaces.

- **X5** One wired cadence constant, structured for per-pattern override later; no editorial per-pattern cadences pre-launch.

## Accepted Scope (added to this plan)

Sequenced: **Phase 1 (correctness)** must land before **Phase 2 (surfaces)**.

Phase 1 — correctness:
- Taxonomy: extend `Movement Pattern #1` vocabulary with Anti-Rotation and Anti-Extension; re-tag the misfiled rows (mostly within the 49 Rotational rows); CHECK-constraint migration ordered as extend-constraint → re-tag → re-validate.
- Credit vectors: movement → weighted multi-pattern credit (TGU → get_up + rotation + push; carries stay carry). Weights are fixed editorial values in the catalog CSV, 0–1 per pattern, normalized to sum to 1 per movement; the doc (docs/pattern-debt-scoring-model.md) is updated first and defines the exact vectors. Replaces first-match single-bucket attribution in SQL + shared TS scorer. SQL and TS must stay in lockstep — a parity test (same fixture through both) is a required deliverable.
- Per-pattern cadence constants driving the recency component (replacing the dead single constant).
- Re-tag validation tooling wired into the movement-catalog ingest: validates the full 251-row catalog (legal pattern + well-formed credit vector per row), fails CI on drift.
- Recompute story: debt is always derived from `movement_logs` at query time, so scores shift once on deploy — expect a one-time visible jump in Weekly Balance; no backfill needed. Release note copy covers it.
- Terminology decision: **user-facing vocabulary is "readiness" + On track/Due/Overdue bands; "debt" is internal model vocabulary only** (doc, code, prompts). UI copy never says "debt".

Phase 2 — surfaces (after Phase 1 correctness ships):
- Per-user pattern preferences: `profiles` column, Account page toggles, filtering in WeeklyBalance and recommender inputs/prompt.
- Post-workout debt delta UI; pays-down badges; debt trend sparklines.
- Debt-optimal session mode: deterministic candidate pre-selection by debt coverage + LLM session shaping. Largest and vaguest item — requires its own spec (/office-hours or /spec) before implementation; cost/latency handled within existing recommender edge-function budget (PROD-85).

Residual risk (accepted): carry (9 movements) and get_up (4) stay thin buckets; credit vectors reduce false debt (TGU pays multiple patterns) but don't fatten the catalog. Revisit at next catalog expansion.
